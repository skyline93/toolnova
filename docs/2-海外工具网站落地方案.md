# 海外工具网站落地方案

本文档基于 [1-海外工具网站项目调研与实施方案](./1-海外工具网站项目调研与实施方案.md)，将战略与阶段目标落实为可执行清单、技术边界与验收标准。

---

## 一、与调研文档的对齐关系

| 调研文档要点 | 落地对应 |
|--------------|----------|
| 综合型工具站（Developer / File / Calculators / Time） | 统一信息架构、`/tools` 索引、分类内链 |
| 一页一工具 = SEO 入口 | 每工具独立 URL、独立 Title/H1/Meta、Schema |
| 技术栈：Next.js + Go/Python + PG + Redis + Docker + CF + S3 | 分阶段引入，避免 MVP 过度工程 |
| 阶段：10 → 30 → 会员/API → 100 页 | 见下文各阶段交付清单 |
| 变现：AdSense → 订阅 → API | 按流量与合规就绪度切换 |

**文档差异说明：** 调研文档「第一阶段」列举 8 个工具但目标为 10 个页面。本方案建议用 **JWT Decoder**、**Age Calculator**（或 **World Clock** / **Workdays Calculator** 之一）补满 10 页。

---

## 二、落地总原则

1. **MVP 优先「可 SEO、可快、可稳定」**  
   首版可不建用户表、不接 Stripe。能在浏览器或 Next.js 内完成的工具（JSON / Base64 / UUID / Timestamp 等）优先纯前端或轻量服务端，减少运维面。

2. **按需引入后端与存储**  
   必须上「重服务」的典型场景：大文件与 CPU（图片压缩、PDF）、持久化（会员/API）、队列与限流（API 商业化）。

3. **每个工具页固定产出物**  
   唯一 URL、Title/H1/Description、简短使用说明、结构化数据（`WebApplication` / `SoftwareApplication`）、移动端可用、Core Web Vitals 不恶化。

## 三、第 0 周：项目基建

| 事项 | 落地动作 |
|------|----------|
| 品牌与域名 | 定英文名与域名（`.com`），检索商标与近似站冲突 |
| 代码与仓库 | Monorepo 或 `web` + `api`；环境 `dev` / `staging` / `prod` |
| 前端骨架 | Next.js（App Router）、统一 Layout、导航、`/tools` 索引 |
| SEO 基础 | `metadata` 模板、sitemap、robots.txt |
| 部署 | Docker；常见组合：**Vercel（前端）+ API 主机** 或 **全栈单 VPS**；前置 **Cloudflare** |
| 观测 | Google Analytics 4、Google Search Console |
| 错误监控 | Sentry（或同类）二选一即可 |
| 合规 | Cookie 同意（若用广告）、Privacy Policy、Terms；文件类写明是否存盘与保留期限 |

**验收：** 正式域名 HTTPS 可访问；Search Console 已验证；GA4 能收到测试事件。

## 四、第一阶段（0–1 个月）：MVP，10 个工具页

### 4.1 工具与实现边界

| 工具 | 建议实现 | 说明 |
|------|----------|------|
| JSON Formatter | 浏览器或 Next 轻量服务端 | 可强调「默认不离开本机」作卖点 |
| UUID Generator | 纯前端 | — |
| Base64 Encode/Decode | 纯前端 | — |
| Timestamp Converter | 纯前端 | 覆盖常见单位与多时区展示 |
| Time Zone Converter | 纯前端（`Intl` / 时区库） | 覆盖 DST，准备测试用例 |
| Date Calculator | 纯前端 | 规则写清（含闰年等） |
| Image Compressor | 后端或 WASM | MVP 限制单文件大小（如 5–10MB） |
| PDF Merge | 后端 | 注意内存与超时；临时文件落 S3 或 tmp + 定时清理 |
| JWT Decoder | 纯前端（补页） | 仅解码展示，密钥验证属后续 |
| Age Calculator | 纯前端（补页） | — |

### 4.2 本阶段交付清单

- [ ] `/tools` 分类与到各工具的内链  
- [ ] 10 个工具页：功能可用 + 英文文案 + 每页独立 meta  
- [ ] 全站移动端可用；首屏与 CLS 可控  
- [ ] sitemap.xml 提交 Search Console  
- [ ] 结构化数据通过 Rich Results 测试（抽样）  

### 4.3 数据库与 Redis

- **可省略**：若仅静态页 + 纯前端/轻 API。  
- **若已做 PDF/图片管线**：可仅用最简任务状态存储；**不推荐**首月仅为「预留」而上全套 PG/Redis。

## 五、第二阶段（1–3 个月）：约 30 页 + 广告

### 5.1 工具扩展（与调研文档一致，分批上线）

每批 3–5 个页面，保持相关工具互链：

- JWT Decoder（若第一阶段已上则深化或换 Cron / JSON to CSV）  
- Regex Tester、Diff Checker  
- Markdown → PDF、JSON → CSV  
- Cron Expression Generator  
- Loan Calculator、ROI Calculator  
- 可选：Compound Interest、Salary/Tax（注意国家/地区版本策略）  

### 5.2 Google AdSense

- 预留广告位，避免破坏 CLS。  
- 用 Search Console 识别先有展示的 URL，优先优化 Title 与首段。  
- 遵守内容与广告政策；文件类工具补充滥用与版权说明。  

### 5.3 SEO 固定模板（执行层）

- Title：主关键词 + 适度修饰词（Online / Free 等），避免堆砌。  
- 每页唯一 H1；首段 100–200 词说明场景；可选 FAQ 扩长尾。  
- `canonical`、避免重复路径；图片与字体优化。  

**验收：** 约 30 个可索引 URL；AdSense 已通过（若申请）；核心 URL 有展示数据可查。

## 六、第三阶段（3–6 个月）：用户、会员、Stripe、API

### 6.1 数据与支付

- **PostgreSQL**：用户、订阅状态、Stripe Customer / Subscription ID 映射。  
- **Stripe**：Checkout + Customer Portal；Webhook 验签 + **幂等**更新本地状态。  

### 6.2 会员权益落地顺序建议

1. 去广告  
2. 提高文件大小/次数上限  
3. 批量处理  
4. 历史记录 / 云端存储  
5. 高级工具与 API 额度  

定价可参考调研文档：Basic $5、Pro $9、Team $19（以实际产品与地区为准调整）。

### 6.3 API 与计费

- API Key、用量（按日/月）；Redis 做限流（如滑动窗口）。  
- 网关：鉴权、配额、429 与错误码规范。  
- 对外文档：OpenAPI + 示例（如 `/docs/api`）。  

### 6.4 服务拆分建议

- 展示与轻逻辑：Next 或 BFF。  
- 重计算（PDF/图片）：独立 **Go 或 Python** 服务，便于单独扩容与隔离故障。  

**验收：** 付费链路打通；Webhook 与订阅状态一致；API 配额与限流可观测。

---

## 七、第四阶段（6–12 个月）：100 页与规模化

- 计算器矩阵（Time Zone、Date、Age、Work Hours、Loan、ROI、Compound、BMI、Salary/Tax 等）：**避免薄内容**——每页有独立首段与使用说明，模板 + 实质差异。  
- 程序化 SEO：内链网清晰，非空壳列表页。  
- API 与会员联动：Pro 含 API 额度。  

**验收：** 可索引页面接近 100；核心词群有稳定展示/点击趋势。

## 八、非功能需求

| 领域 | 要点 |
|------|------|
| 安全 | 上传校验（类型、大小）；若支持 URL 拉取需防 SSRF；视成本考虑恶意文件扫描 |
| 隐私 | 默认「处理完即删」；隐私政策写明日志、GA、广告与第三方 |
| 成本 | S3 生命周期清理临时对象；Cloudflare 缓存静态资源；重任务异步化防 OOM |
| 备份 | 存在用户与订阅数据后，PG 定期备份与恢复演练 |
| 可观测 | MVP 不必上 ELK/Loki；结构化日志 + 错误聚合即可，随规模再演进 |

## 九、指标与周节奏

调研文档公式：**收入 ≈ 页面数 × 单页流量 × 广告单价 × 付费转化率**。

建议每周查看：

- **Search Console**：展示、点击、CTR、平均排名（按 URL）  
- **GA4**：着陆页、跳出率、关键事件  
- **工程**：错误率、P95 延迟、PDF/图片任务失败率  

固定动作：**每周至少 1 次** 新工具上线或既有页重大优化；**每月** 复盘 Top URL 的标题与描述。

## 十、风险与对策

| 风险 | 对策 |
|------|------|
| SEO 冷启动慢（0–3 个月流量偏低） | 长尾词、内链、速度、持续发版；预期与调研文档「收入预期」对齐 |
| 文件类滥用与合规 | 条款、类型/大小限制、必要时人机验证 |
| 过度架构 | 首月不做完整日志中台；按流量与故障数据再引入 |

---

## 十一、建议执行顺序（Checklist）

1. 域名 + Next.js 壳 + `/tools` + SEO 模板 + 部署 + GA4 + Search Console  
2. 先上线 **5 个纯前端工具页**，跑通发布与索引流程  
3. 再上 **Image Compressor + PDF Merge** 的后端与临时文件/S3 清理策略  
4. 补满 **10 页** 并提交 sitemap  
5. 按周扩至 **约 30 页**，申请 **AdSense**  
6. 流量与合规就绪后上 **Stripe 会员**  
7. 重服务稳定后开放 **API + 计费**
