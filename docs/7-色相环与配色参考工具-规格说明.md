# 色相环与配色参考工具 — 产品与技术规格说明

本文档将「日常工具集合」定位下的**可交互色相环 / 配色参考**工具方案完整落盘，涵盖产品目标、交互与功能分层、和谐色数学规则、对比度与 URL 状态、页面与组件边界、国际化与无障碍、测试与分期，以及与 Toolnova 仓库结构的**接入清单**。**色相环渲染首选 HTML Canvas 2D**（实现细则见第 14 节）。实现时可据此拆任务与编写测试用例。

---

## 1. 产品定位与目标

### 1.1 定位

- 产品为**泛日常工具集合**，不局限于开发者或办公场景。
- 本工具定位为：**在浏览器内完成的轻量配色参考**，强调**可交互**、**可输出色值**、**可解释**（为何一组色是和谐的），而非静态示意图。

### 1.2 核心用户价值

用户在约 **30 秒内**完成：

1. 选定主色；
2. 理解与其他颜色的关系（可选阅读简短说明）；
3. 获得 **HEX / RGB / HSL** 等可用色值；
4. **复制**到 Figma、幻灯片、代码或笔记。

### 1.3 竞争力要点

- **一屏闭环**：选色 + 多规则和谐色 + 复制 + 对比度，减少跳转。
- **可解释**：每种和谐规则配一句人话说明；可选展示角度关系。
- **隐私与性能**：纯前端计算，不上传图片（MVP）；与全站「本地处理」叙事一致。
- **无障碍**：色块旁有文字标签，不仅依赖颜色传达信息；对比度提示对齐 WCAG 常用阈值。
- **国际化**：中英文文案与 meta 一致，利于搜索与传播。

### 1.4 成功指标（上线后）

- 停留时长、复制按钮点击率；
- 若启用 URL 分享：带参 URL 的打开次数；
- 从本页跳转到其他工具的比例（是否融入「工具集合」）。

### 1.5 期望与边界（诚实表述）

- 本工具为**屏幕 RGB 配色参考**，不替代专业校色、印前专色或摄影后期完整工作流。
- 不同显示器色域与校准不同，可在文案中一句带过「仅供参考」。

## 3. 颜色模型与内部表示

### 3.1 单一真相源（canonical）

内部统一使用 **HSL**：

| 分量 | 范围 | 说明 |
|------|------|------|
| **H** | `0–360`（浮点） | 色相；`360 ≡ 0`，规范化：`((h % 360) + 360) % 360`。 |
| **S** | `0–1`（推荐） | 与逻辑计算一致；对外展示可写百分比。 |
| **L** | `0–1`（推荐） | 同上。 |

团队需在文档与代码中统一采用 **0–1** 或 **0–100**，二选一；下文以 **0–1** 为例。

### 3.2 色相环与 H 的对应

- 环上角度与 **CSS `hsl` 色相**一致：0° 红、120° 绿、240° 蓝等。
- **产品形态 A（MVP 推荐）**  
  - **环只控制 H**；**S、L** 使用滑条或环旁二维控件（三角/方形可选，二期可增强）。  
  - 实现清晰、触摸友好、开发量可控。  
- **形态 B**  
  - 外圈 H + 内圈 S–L 方阵；视觉更强，实现与测试成本更高，建议二期评估。

### 3.2.1 渲染选型：偏 Canvas

- **色相环（仅表示纯色相 H）**：使用 **`<canvas>` + 2D Context** 绘制与拾取，便于高分屏缩放、拖动时局部重绘与离屏缓存。  
- **S/L 控件**：MVP 可用 **原生 `<input type="range">` 或 Radix Slider**，无需 Canvas。  
- **和谐色色块、预览条、文案**：DOM + CSS，便于复制按钮与无障碍。  
- **SVG** 可作为环的备选（锥形渐变分段），本规格以 **Canvas 为主路径**；若未来改为 SVG，和谐色与对比度逻辑不变，仅替换第 14 节绘制与命中部分。

### 3.3 对外展示与复制

- 默认展示 **HEX**：`#RRGGBB`（大小写全站统一）。  
- 展开或切换：**RGB**（0–255 整数）、**HSL**（与 CSS 一致，建议现代语法如 `hsl(210 80% 50%)`，全站统一一种写法）。

### 3.4 边界与特殊值

| 情况 | 行为 |
|------|------|
| `S = 0` | 灰度；H 仍可调，恢复 `S > 0` 时体现色相。 |
| `L = 0` 或 `1` | 近黑/近白；和谐色仍按公式计算；可弱化提示「极亮/极暗时搭配仅供参考」。 |
| 非法 HEX 输入 | 校验失败，错误提示，不覆盖当前有效状态。 |

### 3.5 色彩空间说明（文案）

- 环上选色基于 **HSL**；若面向摄影用户，可注明「屏幕 RGB 参考，非印前专色」。

## 4. 和谐规则：角度表与色块数量

以下均以主色 **`(H, S, L)`** 为基准。MVP 默认：**衍生色继承相同 S、L**，仅改变 **H**（用户易懂、实现简单）。进阶可选「辅色略降饱和」等，列为二期。

记 `H` 已规范到 `[0, 360)`。

### 4.1 互补（Complementary）

- **色块数**：2  
- **色相**：`H`，`(H + 180) % 360`

### 4.2 分裂互补（Split-complementary）

- **色块数**：3  
- **色相**：`H`，`(H + 150) % 360`，`(H + 210) % 360`  
- 说明：与 180° 各差约 30°，对比略柔和于纯互补。

### 4.3 三角配色（Triadic）

- **色块数**：3  
- **色相**：`H`，`(H + 120) % 360`，`(H + 240) % 360`

### 4.4 四元 / 方形（Tetradic）

- **色块数**：4  
- **色相**：`H`，`(H + 90) % 360`，`(H + 180) % 360`，`(H + 270) % 360`  
- 建议：**二期**或折叠为「进阶」，避免 MVP 规则过多。

### 4.5 类似色（Analogous）

- **色块数**：5（可配置为 3 或 7，默认 5）  
- **色相**：`H-60`，`H-30`，`H`，`H+30`，`H+60`（每项再 `% 360`）

### 4.6 单色（Monochromatic）

- **色块数**：5  
- **策略**：固定 **H、S**，围绕当前 **L** 生成阶梯，避免全黑全白占满。  
- **示例公式**：`L_k = clamp(L + (k - 2) * 0.15, 0.05, 0.95)`，`k = 0..4`（步进与 clamp 可在实现时微调并写入单元测试）。

### 4.7 MVP 规则集合建议

- **首期**：互补、分裂互补、三角、类似、单色（5 种）。  
- **首期可不含**：四元（或作为折叠项）。

## 5. 对比度模块

### 5.1 计算标准

- 使用 **WCAG 2.x** 相对亮度（sRGB 线性化）。  
- 对比度：`C = (L_lighter + 0.05) / (L_darker + 0.05)`。

### 5.2 输出

- 主色相对 **`#FFFFFF`**、相对 **`#000000`** 两个比值。  
- 文案阈值参考：  
  - 普通文本 **AA**：≥ 4.5:1  
  - 大文本 **AA**：≥ 3:1  
  - **AAA**：7:1 / 4.5:1（可简化为「达标 / 未达标」减少噪音）

### 5.3 预览条

- 一行：**主色背景 + 白字**（短词）；一行：**主色背景 + 黑字**。  
- **不建议**用 text-shadow 强行提高可读性后再宣称达标；预览与数字保持一致，诚实展示。

## 6. URL 状态与分享

### 6.1 推荐格式

- **主选**：`?hex=RRGGBB`（无 `#`，6 位十六进制，大小写不敏感）。  
  - 优点：短、易分享、与复制习惯一致。  
- **备选**：`?h=...&s=...&l=...`（单位必须与内部状态文档一致）。  

若同时存在多种参数，优先级约定：**`hex` 优先于 `h/s/l`**，避免不一致。

### 6.2 历史记录

- 拖动环时高频更新：使用 **`replaceState`** + **防抖 200–300ms**，避免历史栈爆炸。

### 6.3 非法参数

- 解析失败时回退默认色（例如 `H=220, S=0.75, L=0.5`），并可选用轻提示说明 URL 无效。

## 14. Canvas 实现细则（色相环）

本节约定 **形态 A**：环上仅表达 **H**（取 **S=100%、L=50%** 的「全饱和中间明度」色带）；用户当前真实主色仍由全局 **H/S/L** 状态决定，环旁大块预览与数值区反映完整 **HSL**。

### 14.1 画布布局与坐标系

| 概念 | 约定 |
|------|------|
| **逻辑尺寸** | 以 **CSS 像素**为基准定义几何（中心 `cx, cy`、外半径 `R`、内半径 `r`），便于命中计算与 UI 对齐。 |
| **外径 R / 内径 r** | 环带厚度 `R - r` 建议 **24–40 CSS px**（移动端可略厚）；内圆可填主色预览或留空。 |
| **devicePixelRatio** | `dpr = min(window.devicePixelRatio ?? 1, 2)`（或 2.5 上限），避免极端高分屏内存过大。 |
| **位图尺寸** | `canvas.width = floor(cssWidth * dpr)`，`canvas.height = floor(cssHeight * dpr)`。 |
| **变换** | `ctx.setTransform(dpr, 0, 0, dpr, 0, 0)` 或等价 `scale(dpr,dpr)`，之后**所有绘制与路径均使用 CSS 像素坐标**。 |
| **ResizeObserver** | 外层容器尺寸变化时：更新 canvas 的 CSS 宽高属性、重算 `width/height`、**使离屏环缓存失效**并重绘。 |

### 14.2 色相环绘制策略（推荐：分段扇形 + 离屏缓存）

**目标**：在环带上显示 **0°–360°** 连续色相，且与 **CSS `hsl(H 100% 50%)`** 一致。

**方案 A（推荐）— 扇形离散逼近**

1. 将整环分为 **N 段**（例如 **N = 120 / 180 / 360**）。  
   - N 越大接缝越不明显，但 `path` 次数增加；**120** 在移动端通常已足够平滑。  
2. 对第 `i` 段（`i = 0..N-1`）：  
   - 起止弧度 `a0`、`a1` 与 **Canvas 2D `arc()` 的角方向**一致：API **默认顺时针**为正方向（与数学上常见的逆时针「正角」相反）。分段时须保证 **沿环递增方向** 与 §14.4 中 **H 顺时针增大** 的约定一致；若用数学逆时针角，可对该段 `arc(..., counterclockwise: true)` 或交换 `a0/a1`。  
   - 该段代表色相 `H_i = (i / N) * 360`（或与角度映射一致后取中点 `H_mid` 填色，减少偏色）。  
   - `ctx.fillStyle = hsl(H_mid, 100%, 50%)`（与项目统一 CSS 颜色字符串格式）。  
   - 路径：`moveTo` 内弧点 → `arc(cx, cy, R, a0, a1)` → `arc` 内圆 **反向** 闭合（或 `lineTo` 连接内外弧），`fill()`。  
3. **抗锯齿**：环边缘可 `stroke` 极细透明边或保持背景对比；避免段与段之间 1px 露底可让相邻段 **轻微重叠 0.5px**（可选）。

**离屏缓存（强烈建议）**

- 色相环在 **S/L 不变时**（环本身固定为 100%/50%）**静态**。  
- 首次绘制或 resize 后：在 **`OffscreenCanvas` 或内存 `HTMLCanvasElement`** 上画完整环，主 canvas 每帧 `drawImage(cache, 0, 0)`。  
- **拖动时**：主 canvas 仅 **清屏 → 贴缓存 → 绘指示器**（指针、高亮扇区可选），避免每帧重画 360 段扇形。

**不推荐**

- **逐像素极坐标填充**：CPU 成本高，移动端易掉帧。  
- **单段 `createConicGradient`**：若目标浏览器矩阵覆盖足够，可作为简化实现；需注意 **与分段法在旧浏览器上的回退**（规格不强制，由实现选型）。

### 14.3 指示器（当前 H）

- 在 **半径约 `(R + r) / 2`** 处（环带中心线）放置 **小圆点、短刻度线或小三角**，角度对应当前 **H**。  
- 绘制顺序：先贴离屏环，再 `save()` → `translate(cx,cy)` → `rotate(angleRad)` → 在环带中心线位置画指示器 → `restore()`。  
- **角度 `angleRad` 与 H 的映射必须与 14.4 完全一致**（同一函数 `hueToAngleRad` / `angleRadToHue`）。

### 14.4 命中测试：指针 ↔ 色相 H

**输入**：相对于 canvas 左上角的 **CSS 像素坐标** `(px, py)`（由指针事件换算，见 14.6）。

1. `dx = px - cx`，`dy = py - cy`。  
2. `dist = hypot(dx, dy)`。  
3. **环内有效**：`r - ε <= dist <= R + ε`（`ε` 取 **2–4 CSS px** 扩大热区，改善触摸）。  
4. **角度**：Canvas 坐标系 **y 轴向下**。采用数学 `θ = atan2(dy, dx)`（范围 `(-π, π]`，`0` 为 **3 点钟方向**）。

**H 与 θ 的映射（须在实现中二选一并写死，建议如下）**

- 目标：与常见「**红在上方、顺时针增大**」色环直觉一致，且与 **CSS H=0 红** 对齐。  
- 一种常用约定：  
  - `H = (90 - deg(θ) + 360) % 360`  
  - 即：**正上方**（`dx=0, dy<0`）对应 **H≈0（红）**，顺时针 H 增加。  
- **反算**：`θ = (90 - H) * π/180`（用于画指示器）。

**首次实现验收**：在 `H=0,120,240` 等处采样环上颜色或对照指示器方位，与浏览器中 `hsl(H 100% 50%)` **目视一致**；并增加 **单元测试或 E2E** 锁定 `angleRadToHue` / `hueToAngleRad` 互逆（允许浮点误差）。

### 14.5 指针事件与滚动抢占

- 使用 **`pointerdown` / `pointermove` / `pointerup` / `pointercancel`**（统一鼠标与触摸）。  
- `pointerdown` 在环有效区内：`setPointerCapture(pointerId)`，在 **document 或 canvas** 上监听 `pointermove`/`pointerup`，避免滑出元素后丢跟踪。  
- 外层包裹元素设置 **`touch-action: none`**，避免拖动环时页面滚动。  
- `pointermove` 内：**节流到 rAF**（见 14.7），更新 `H` 状态；由 React 状态驱动指示器重绘时注意避免过度 render（可将「仅 canvas 重绘」放在 `useRef` + rAF 路径，状态仍可按帧或 pointerup 提交）。

### 14.6 事件坐标到 CSS 像素

从 `PointerEvent` 获取相对于 canvas 的坐标：

- `const rect = canvas.getBoundingClientRect();`  
- `px = event.clientX - rect.left;`  
- `py = event.clientY - rect.top;`  
- 若 canvas 的 **CSS 宽高**与 **属性 width/height 比** 不是 1:1（未用 transform 缩放逻辑坐标时），需乘以 `canvas.width / rect.width` 等换算；**推荐**采用 14.1 的 **`setTransform(dpr)` + CSS 尺寸 = 逻辑尺寸**，使 `px, py` 直接为逻辑坐标。

### 14.7 动画与重绘节奏

| 场景 | 策略 |
|------|------|
| 拖动环 | `pointermove` 只写入 **`pendingHue`**；**单例 `requestAnimationFrame`** 在下一帧读取 `pendingHue`、更新指示器、`drawImage` 缓存 + 指针，合并多事件。 |
| S/L 滑条变化 | 主色预览变，**无需重画色相环缓存**；仅更新 DOM 预览与和谐色。 |
| `prefers-reduced-motion` | 指示器可 **取消缓动**，直接跳变；环本身无动画即可。 |

### 14.8 Canvas 与无障碍（配合而非替代）

- Canvas 像素本身对读屏不友好：必须提供 **等效选色途径**。  
- **MVP 必做**：**H 数值输入**或 **H 的 range 滑条**（0–360），与环双向绑定；读屏可聚焦该控件。  
- `canvas` 元素：`aria-label` 引用文案键 `ariaColorWheel`；可用 `role="img"` **仅当**说明「配合下方滑块使用」或类似（避免宣称可完全键盘操作 canvas 像素）。  
- 焦点顺序仍遵循第 7 节：环（或跳过 canvas 焦点到滑块）→ S → L → …

### 14.9 颜色字符串与 `fillStyle`

- 优先使用浏览器支持的 **`hsl(H 100% 50%)`** 现代语法；若需兼容旧引擎，可封装 `formatHslForCanvas(h, s, l)`。  
- 和谐色块与对比度计算仍在 **sRGB + HSL 逻辑**中完成，与环上 `fillStyle` 一致即可。

### 14.10 性能与内存小结

- 和谐色与对比度为 **O(1)**，非瓶颈。  
- 瓶颈在：**分段数 N**、**dpr**、**每帧全量重画环**。**离屏缓存 + 拖动只画指示器** 为必选项。  
- 可选：`will-change: transform` 给外层 wrapper 无必要；避免超大 canvas（如全屏环）在非必要时限制 **max-width**。

### 14.11 Canvas 相关测试补充（接第 13 节）

1. **映射互逆**：`hueToAngleRad(angleRadToHue(θ)) ≈ θ`（在有效环带半径内取点反算）。  
2. **Resize**：改变容器宽度后，命中仍正确（中心与 R、r 比例不变或按比例缩放后仍一致）。  
3. **dpr**：`dpr=2` 时环带无异常拉伸（逻辑坐标与 `getBoundingClientRect` 一致）。  
4. **Pointer capture**：按下后移出 canvas 仍持续更新 H，直至 `pointerup`。
